# 开发文档：键盘和弦标记 + 钢琴试听与时间对齐

> 项目：chordDeck（FastAPI + Vue3/Vite 和弦识别 Web 应用）
> 文档版本：v1.0 · 2026-09-02

---

## 1. 背景与目标

当前 Web 应用已完成和弦识别、时间轴标记、历史缓存与引擎切换，但缺少两个能力：

1. **和弦的可视化形态**：用户只能看到和弦名（如 `Cmaj7`），看不到它的实际构成（哪些键）；
2. **听感核对**：无法知道识别结果听起来对不对，也无法修正「和弦时间轴与原曲错位」的问题。

本次迭代（纯前端，后端零改动）新增：

- **钢琴键盘和弦标记**：在播放器区域显示键盘，随播放实时点亮当前和弦的构成音；
- **钢琴试听**：播放到某个和弦时，可（可选地）自动播放该和弦的钢琴声用于核对；
- **双路音量**：原曲音量、钢琴音量两个独立控制条；
- **钢琴声音开关**；
- **和弦时间偏移**：全局 ±5.0s、步进 0.1s 的偏移调节，用于修正识别时间轴与原曲的错位。

风格约束：与现有「高端克制」主题一致（近黑暖底、低饱和金点缀、细线、衬线标题、克制动效），
不使用与现有视觉冲突的新配色。

## 3. 需求拆解与验收标准

| # | 需求 | 验收标准 |
| --- | --- | --- |
| R1 | 键盘显示当前和弦构成音 | 播放中当前和弦（按偏移后时间）的构成键被点亮；和弦名旁显示级数（R/3/5…） |
| R2 | 钢琴声音开关 | 关闭时播放不发声；开启时和弦变化处自动播放一次钢琴声 |
| R3 | 原曲/钢琴独立音量 | 两个滑块分别控制 `<audio>.volume` 与钢琴引擎主增益，互不影响 |
| R4 | 时间偏移 0.1s 调节 | `−`/`+` 步进 0.1s，范围 ±5.0s；显示当前偏移值；可一键归零 |
| R5 | 手动试听 | 当前和弦旁有「试听」按钮，随时单次播放当前和弦 |
| R6 | 风格一致 | 键盘与控件使用现有 CSS 变量（--accent 等），暗色主题无违和 |

## 4. 总体设计

**纯前端实现**；后端 `/api/analyze` 返回的 `chords/chords_simple` 已含时间戳与标签，足以支撑全部功能。

```
ChordTimeline.vue（改造，持播放状态机）
 ├─ 监听 <audio> timeupdate / rAF 驱动 current
 ├─ effective = current + offset            ← 所有和弦查询基于 effective
 ├─ 和弦查询 → activeChord（含构成音 voicing）
 ├─ 变化侦测 → pianoOn && 播放中 → piano.playChord(voicing)   [R2]
 ├─ 手动试听按钮 → piano.playChord(voicing)                    [R5]
 └─ 控件行：钢琴开关 · 原曲音量 · 钢琴音量 · 偏移调节            [R2/R3/R4]

PianoKeyboard.vue（新）
 └─ props: highlighted(键位标记表) → 渲染 C3–B4 键盘 + 点亮 + 级数标签

lib/music.js（新）   和弦名 → 半音集合 / midi voicing / 级数标签
lib/piano.js（新）   采样优先 + 合成兜底的钢琴引擎（含抢占、主增益、解锁策略）
```

### 4.1 数据流（时间偏移语义，关键）

- 音频播放时间为 `current`（由 `<audio>` 驱动，0..duration）。
- 定义 **`effective = current + offset`**，其中 `offset ∈ [-5.0, +5.0]`，步进 0.1。
- **所有和弦相关逻辑（当前和弦显示、键盘点亮、钢琴自动触发）一律基于 `effective`**，
  时间轴标点位置仍按 `current` 播放进度绘制（标点是"原曲位置"，不应随偏移移动）。
- 语义示例：若某歌和弦标记整体比听感**早 0.3s**（声音到了和弦还没切），
  把 offset 调为 **+0.3**：`effective` 后移，和弦查询延后到与听感对齐。
  （方向以听感为准，提供 +/− 双向即可；文档记录默认语义：正偏移=和弦判定延后。）

### 4.2 钢琴触发逻辑（防抖与防骚扰）

- 自动触发条件：`playing === true && pianoOn === true && activeChord 变化`。
- **拖动/点击时间轴（scrub）期间不自动触发**（`dragging` 标志抑制）；
  松手后若 chord 已变化则补一次触发（让用户听到跳转处的和弦）。
- 每次触发前 `piano.stop()` 抢占上一和弦（快衰减，避免糊成一团）。
- 同一和弦内不做重复触发（按 `activeIdx` 变化而非时间变化判断）。

## 5. 模块设计

### 5.1 `frontend/src/lib/music.js`

```js
NOTE_PC = { C:0, Db:1, D:2, Eb:3, E:4, F:5, F#:6, G:7, Ab:8, A:9, Bb:10, B:11 }  // 含升号同音
CHORD_FORMULAS = [ { id:'maj', intervals:[0,4,7] }, { id:'m', ... }, ... ]      // 36 种（移植 chordE）

parseChordLabel(label) → { rootPc, intervals[], bassPc|null } | null  // 'N'/未知 → null
  - 取根音前缀（C/Ab/Bb…）→ 后缀查公式表（精确匹配 + 归一化兜底：剥离 6/9/add 等）
  - 支持 slash（D/F# → bass=F#）与转位显示
voicing(pc, intervals, {center=60, lo=48, hi=71}) → midi[]
  - 根音落 center=60（C4），各音按 interval 累加并折叠进 [lo,hi]（采样最优点）
degreeLabels(intervals) → ['R','3','5',...]        // intervalToDegreeLabel 移植
midiToNoteName / noteNameToPitchClass / mod12 / midiToPc
```

### 5.2 `frontend/src/lib/piano.js`

```js
class PianoEngine {
  ensureCtx()          // AudioContext 惰性创建（用户手势解锁）
  setEnabled(on)       // 控制是否发声（R2）
  setVolume(v 0..1)    // 主增益（R3）：增益 = v * 0.5（采样 0.95/音，需压总电平）
  playChord(midis)     // 抢占式：stop() → 逐音 playMidi()
  playMidi(midi)       // 采样优先：缓存 fetch/decode；失败回退振荡器
  stop()               // 快衰减当前活动振荡器/采样源
  release()            // 组件卸载时关闭 ctx
}
采样缓存：Map<noteName, AudioBuffer>，首次 fetch + decode 后复用；
首音延迟可接受（本地 4.5MB/24 文件小）；可预取当前歌全部 24 音（并发 fetch）。
```

### 5.3 `frontend/src/components/PianoKeyboard.vue`

- 属性：`keys: Array<{midi, on, label?}>`（由父组件按 24 键 C3–B4 计算）或直接传
  `highlight: Map<midi,string|''>`；`disabled`（无当前和弦时键盘整体变暗）。
- 渲染：与 chordE 相同的绝对定位键布局；白键/黑键分开两组；键宽按容器自适应（等比缩放）。
- 点亮样式（沿用现有令牌）：
  - 白键激活：`background: var(--accent)` 淡金填充 + 文字深色；
  - 黑键激活：`background: var(--accent)`；
  - 级数标签（R/3/5/b7…）：激活键上的小号 mono 标签（深色文字）；
  - 根音键比其余略强（金色边框或加粗标签）。
- 纯展示组件，无交互逻辑（试听按钮在父组件）。

### 5.4 `ChordTimeline.vue` 改造

新增响应式状态：

```js
pianoOn = ref(false)          // R2（localStorage 持久化）
volOriginal = ref(80)         // R3 0..100
volPiano    = ref(50)
offset      = ref(0)          // R4 -50..50 单位 0.1s（存 0.1 刻度整数避免浮点误差）
offsetSec   = computed(() => offset.value * 0.1)
effective   = computed(() => current.value + offsetSec.value)
activeChord = computed(() => chords.findLast(c => c.timestamp <= effective))  // 现有 activeIdx 改用 effective
```

- `<audio :volume>` 由 `volOriginal/100` 驱动（watch 同步）。
- 钢琴开关 watch：开启时先 `piano.unlock()`（用户手势内），随后音频节拍触发的 playChord 生效。
- 键盘数据：`activeChord` 非 'N' → `parseChordLabel` → voicing → 键盘点亮表（含级数标签）；'N'/空 → 键盘熄灭。
- 控件行（transport 下方新行，全部用现有 caption/seg/滑块样式）：
  ```
  [钢琴声音 ● 开关] [原曲 ──●──] [钢琴 ──●──]  |  和弦偏移 −[0.3s]+ [归零]
  ```
  - 音量滑块：`<input type=range>`，自定义轨道/拇指样式（细 2px 轨道 + 金点拇指）。
  - 偏移：`−`/`+` 圆形小按钮（点击 ±1 刻度=0.1s），中间显示 `+0.3s`，长按不重复（避免误触），
    「归零」小按钮仅在非 0 时出现。
- 持久化：pianoOn / 两音量 → localStorage 全局键；offset → localStorage 按 `result.id` 键
  （每首歌独立，切歌恢复）。

## 8. 边界情况

| 场景 | 行为 |
| --- | --- |
| 当前和弦为 N / 无和弦 | 键盘熄灭；不触发钢琴 |
| 未知标签（引擎未来扩展） | `parseChordLabel` 返回 null → 熄灭，不崩 |
| scrub 拖动 | 抑制自动触发；松手补一次 |
| 偏移使 effective 越界（<0 或 >duration） | 和弦查询自然返回首/末标记（findLast 语义），不崩溃 |
| 浏览器禁自动播放 | 首次开启钢琴/点击播放时在用户手势内 `ctx.resume()`；仍失败则键盘功能正常、声音不可用（提示即可） |
| 采样文件缺失（离线/损坏） | 自动回退振荡器合成音 |
| 和弦极长/极短 | 触发只发生在和弦切换点，与时长无关 |

## 9. 测试计划

1. **单测（node）**：`parseChordLabel` 覆盖简化与完整标签（`C`/`Bbm`/`G7`/`Cmaj7`/`D/F#`/`N`/未知）；
   voicing 折叠到 [48,71]；级数标签映射。
2. **构建**：`npm run build` 通过；产物含键盘与控件文案。
3. **冒烟（curl + 静态检查）**：SPA 200；`/samples/C4.mp3` 200。
4. **人工听感验收（用户）**：真机上播放真实歌曲，验证
   - 键盘随和弦点亮/熄灭；
   - 开钢琴声音后和弦切换处有钢琴声；关后静默；
   - 两音量滑块独立生效；
   - 偏移 ±0.1s 步进下和弦判定与听感对齐（用「搬家前」「心碎烧酒」两首验收）。

## 11. 风险

- **采样大小**：4.5MB 前端资源，可接受（本地应用）；如介意可删采样目录即自动用合成音。
- **自动播放策略**：iOS/Safari 对 AudioContext 限制最严，已在用户手势内解锁；若个别场景无声，
  提示用户先点一次播放即可（常见做法）。
- **键盘宽度**：2 个八度在 860px 页面内充裕；窄屏时按容器等比缩放（transform: scale 或 flex）。
- 后端无改动，风险面小；现有缓存/历史/引擎功能不受影响。
